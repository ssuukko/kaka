# KAKA 구조

## 목적

회사 Windows PC의 ORCA 일반 터미널 탭에서 기존 카카오톡 대화를 직접 읽고 입력한다.
AI 지시, 자동 답장, MCP 서버 기능은 제품에 포함하지 않는다.

## 구성

| 파일 | 책임 |
| --- | --- |
| `app.py` | 방 검색·선택, RichLog 대화, TextArea 작성, 키보드·화면 스크롤 |
| `session.py` | 방별 상태, 조회 직렬화, 페이지 수집, 전송 직렬화·확인 |
| `models.py` | 문자열 ID, 시간대, 메시지 중복·수정 처리, 전송 기록 매칭 |
| `backends/nichirin.py` | 고정 엔진 공개 CLI 호출, 오류·타임아웃·종료 처리 |
| `backends/_worker.py` | stdin 요청을 공개 모듈 진입점으로 전달 |
| `backends/demo.py` | 실제 계정에 접근하지 않는 합성 데이터 |
| `__main__.py` | 실행 옵션, 진단 명령 |

## 대화 갱신

첫 선택에서 최근 100개를 읽는다. 이후 마지막 메시지 ID보다 새로운 영역을 가져오며,
최신 페이지 전체가 아직 새 영역이면 `--before-id`로 이전 페이지를 조회해 기존 커서까지 잇는다.
모든 페이지를 검증하고 나서 상태를 합친다. 중간 실패는 커서를 전진시키지 않는다.
최대 50페이지를 넘으면 명시적 오류를 내고 기존 커서를 유지한다.

메시지 ID는 문자열로 보존하고 비교할 때만 Python 정수로 변환한다. 키는 방별로 관리한다.
같은 ID의 수정은 교체하고, 다른 방의 데이터가 섞인 응답은 배치 전체를 거부한다.
과거 페이지는 사용자가 Ctrl+P로 추가한다. 수신 확인과 과거 조회는 방별 lock으로 순서를 지킨다.

## 전송

1. Enter 시점에 방 ID·본문을 고정한다. 이후 방 전환은 이 요청을 바꾸지 않는다.
2. 실제 전송 전 대화를 읽어 기준 ID를 갱신한다. 조회에 실패하면 보내지 않는다.
3. 최소 2초 전송 간격을 지키고 한 번만 호출한다. 본문은 stdin으로 전달한다.
4. 명시적 `not_delivered`는 미전송, 나머지 오류/타임아웃은 미확인으로 처리한다.
5. `submitted`는 클라이언트 제출일 뿐이다. 기준보다 새 ID·`fromMe`·동일 본문을 가진 기록을
   읽었을 때 기록 확인으로 전환한다. 하나의 기록은 하나의 전송에만 매칭한다.
6. 미확인 요청은 자동 재전송하지 않는다. 30초 동안 기록이 안 보이면 상태를 미확인으로 바꾼다.

전송·수신·방 선택은 UI 밖의 비동기 worker에서 진행한다. 실제 엔진 작업은 별도 프로세스에서
실행해 Textual 입력을 막지 않는다. 타임아웃·취소 시 프로세스를 종료하고 회수한다.

## 데이터와 표시

대화·방 이름·초안은 앱 메모리에만 존재한다. KAKA는 자체 대화 DB·원문 로그를 만들지 않는다.
화면은 Rich `Text`로 렌더링하고 메시지의 마크업을 실행하지 않는다. ANSI/OSC·제어 문자는
표시 전에 제거한다. 표시는 OS 로컬 시간대로 변환한다.

대화 기록과 초안은 종료 시 사라진다. 메모리 보관량은 세션에서 조회한 양만큼 늘어난다.
계정을 전환할 때는 앱을 재시작해야 한다. 엔진은 자신의 로컬 캐시를 따로 사용할 수 있다.

## 제한

- 저수준 카카오 연동은 외부 MIT 엔진에 의존한다. 직접 구현한 부분과 명확히 구분한다.
- Windows 실제 카카오톡 실행은 이 개발 환경에서 검증할 수 없다.
- 실제 ORCA의 한글 IME 조합, 잠금/RDP 해제, 첨부파일·이미지 표시 등은 실측 또는 후속 개발 대상이다.
- 다른 방의 실시간 본문은 읽지 않는다. 현재 방은 2초, 목록은 약 15초마다 갱신한다.
- 로컬에서 읽는 동작만으로 카카오 서버의 읽음 상태를 변경하지 않는다.
- 이름이 동일한 여러 방은 UI에서 ID로 구분해 선택하나, 최종 전송 창을 확정하는 것은 엔진의 책임이다.
  실기 검증에서 동일 제목의 방이 오발송 없이 거절되는지 확인해야 한다.
