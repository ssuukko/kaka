### 검증한 동작

- 2^53을 넘는 ID 보존, 동일 ID의 중복·수정 처리, 혼합 방 응답 전체 거부.
- 한 번에 350개의 메시지가 쌓인 경우 페이지를 넘겨 모두 반영.
- 페이지 중간 오류 시 기존 커서를 보존하고 다음 갱신에서 복구.
- 전송 타임아웃은 재시도하지 않고, 실제 기록이 나타나면 상태 확인.
- 전송 전 조회 실패 시 쓰기 미실행, Enter 연타 중복 쓰기 차단.
- 전송 중 다른 방을 선택해도 원래 방으로만 전송, 새 방의 초안 보존.
- 동일 문장의 여러 요청에 같은 기록을 중복 매칭하지 않음.
- 자식 프로세스 타임아웃 종료·회수, stdin Unicode/줄바꿈/셸 특수문자 왕복.
- 원문 출력이나 메시지 본문을 오류/프로세스 명령행에 노출하지 않음.
- 고정한 upstream의 합성 JSON fixture를 실제 어댑터로 해석.
- Textual headless UI에서 방 선택·검색·한글/이모지 입력·직접 전송·초안 복구.
- 여러 줄 붙여넣기와 Ctrl+J가 전송을 유발하지 않음.
- 새 메시지가 와도 스크롤 위치·작성 중 초안 보존.
- 60×22 좁은 화면에서 목록 접기·입력 유지.

## 아직 검증하지 않은 범위

**위 통과 결과는 실제 Windows 카카오톡 전송 성공을 의미하지 않는다.**
실제 KakaoTalk.exe, 로컬 암호화 DB, Win32 전송 창, ORCA의 Windows IME를 사용한 검증은 남아 있다.
`scripts/setup.ps1`의 전체 Windows 설치도 로컬 환경에서는 실행하지 않았다.
CI에는 Windows/Linux의 합성 테스트와 Windows PowerShell 구문 검사를 등록했다.
원격 CI 실행 결과는 GitHub Actions에서 확인한다.

## 사용자 PC 실기 확인 순서

1. Python·카톡이 모두 64비트인지 확인하고 `scripts/setup.ps1`을 실행한다.
2. `start.ps1 -Demo`에서 한글 조합, 띄어쓰기, Enter, Ctrl+J, 여러 줄 붙여넣기를 확인한다.
3. PC 카톡에 로그인하고 **나와의 채팅**을 연 뒤 `start.ps1 -Doctor`를 실행한다.
4. `start.ps1 -Room "나와의 채팅"`에서 기존 텍스트와 발신자·시각을 확인한다.
5. 고유한 테스트 문장 한 건을 직접 보내고 모바일/PC 카톡에서 **한 건만** 도착했는지 확인한다.
6. 모바일에서 새 문장을 보내 TUI에 표시되는지 확인한다. 같은 문장을 연속 두 번 보낸 경우 두 건이 남아야 한다.
7. 여러 줄/이모지 입력, 스크롤 중 수신, 방 전환 중 초안 보존을 확인한다.
8. PC 카톡 종료·재로그인 뒤 F5로 오류 표시와 복구를 확인한다.
9. 동일 제목의 방, 잠긴 방, 카톡 업데이트, 화면 잠금/RDP 연결 종료는 별도 확인한다.
10. 실기 결과는 실제 대화 원문·ID·연락처를 포함하지 않고 OS/카톡/ORCA 버전과 성공 여부만 기록한다.

## 알려진 제품 제한

- 텍스트 중심. 첨부 전송·인라인 이미지·통화·이모티콘 렌더링은 구현하지 않았다.
- 엔진은 외부 MIT 프로젝트의 고정 버전을 사용한다. 저수준 카톡 프로토콜을 새로 구현한 것이 아니다.
- 터미널에서 읽은 상태와 카카오 서버의 읽음 상태는 자동 동기화되지 않는다.
- 계정 전환 시 KAKA 재시작 필요. 초안·대화는 앱 종료 후 복원하지 않는다.
- 실제 메시지 전송은 되돌릴 수 없고, 미확인 상태는 사용자가 원래 카톡에서 확인해야 한다.
